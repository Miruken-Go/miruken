# Delivery Layer: HTTP & JSON (`api/` tree)

Module: `github.com/miruken-go/miruken` (root), except `api/http/httpsrv/openapi` which is its **own** go.mod submodule.

This is the "Spring-Boot-controller-equivalent" layer. It is built entirely as *Features* on top of the core Handler/Callback/Policy/Filter engine (see `reference/core-dispatch.md`) — nothing here changes core semantics, it only adds handler types whose methods use the `_ *struct{ handles.It; ... }` annotation-simulation idiom, `provides.It`/`creates.It` bindings, and `maps.It` (object-mapping policy, see `reference/eventsourcing-support.md` §Maps) for serialization concerns.

## 1. Overview

Layering, outermost to innermost:

```
net/http (stdlib)
  → httpsrv.Use/Api (adapts std http.Handler <-> miruken.Handler, per-request child Context)
    → httpsrv Middleware pipeline (auth, logging, etc. — httpsrv/pipeline.go)
      → httpsrv.PolyHandler (generic /process, /publish endpoint — httpsrv/poly.go)
        → maps.It pipeline (Content-Type/Accept driven marshal/unmarshal — api/json/stdjson)
          → api.Send / api.Publish / api.Post (root/api/message.go — thin wrappers over handles.Command/Request/CommandAll)
            → core Handler.Handle(...) dispatch (reference/core-dispatch.md)
```

Every cross-cutting concern (routing to a remote node, batching, auth, status-code mapping, JSON shape, multipart, polymorphic type resolution) is a `Feature` (`setup.Feature`) registering handler types whose methods declare intent via the struct-tag/marker-embedding idiom — there is no hand-rolled middleware chain of `if err != nil { ... }` type-switches for these concerns; see §7/§8 for the one arguable exception (`PolyHandler`, which is intentionally the "glue" edge adapter).

Each `Feature()` constructor returns a `setup.Feature` built from an `Installer` struct with `Install(b *setup.Builder) error` (registers `b.Specs(...)`) and optionally `DependsOn() []setup.Feature` (declares upstream Features, e.g. `api/http/feature.go:12` depends on `validates.Feature()` + `api.Feature()`). This dependency graph is resolved by `setup/` — see `reference/setup-context.md`.

## 2. Message Envelope & Polymorphism

- **`api.Message`** (`api/message.go:15`) — `struct{ Payload any }`, the universal envelope. `api.Post`/`api.Send[T]`/`api.Publish` (`api/message.go:44,71,97`) each: panic on nil handler/message, create a fresh request-scoped `Stash` via `miruken.AddHandlers(handler, NewStash(false))` (transit-state storage, §below), recover-wrap panics into errors, and delegate to `handles.Command` / `handles.Request[T]` / `handles.CommandAll` respectively (thin generic wrappers in `handles/it.go` over `miruken.Command`/`Execute`/`CommandAll`).
- **`api.Surrogate`** interface (`api/message.go:20-22`): `Original(miruken.Handler) (any, error)` — the contract for "wire-shape ↔ domain-shape" substitution, implemented by every JSON surrogate type in `api/json` and `api/json/stdjson` (§7).
- **Polymorphism** (`api/poly.go`): `Polymorphism` is a bitmask option (`PolymorphismRoot`/`PolymorphismNone`) carried via `miruken.Options(Options{...})` builders `Polymorphic`/`NoPolymorphism`. `GoPolymorphism.TypeInfo` (`api/poly.go:65`) is a **`maps.It`** handler (tag `to:"type:info"`) that turns a Go value's `reflect.Type` string into `{TypeField:"@type", TypeValue:<pkg.Type>, ValuesField:"@values"}` — this is what stdjson's `typeContainer` calls to label a value on the wire.
  - `GoPolymorphism.Static` (`api/poly.go:82`) is a striking, large-scale instance of the annotation-simulation idiom: a single method declares **28 separate `_ creates.It` fields**, each with a distinct `key:"<primitive-type-name>"` tag, registering one covariant binding per Go primitive/slice-of-primitive type-name string so `creates.Key[any](handler, "int64")` etc. resolves without reflection at request time.
  - `GoPolymorphism.Dynamic` (`api/poly.go:125`) handles the general case (arbitrary registered types, incl. `*T` and `[]T` type-id strings) with a lock-guarded `atomic.Pointer[map[string]any]` copy-on-write prototype cache — same idiom as `policy.go`'s `bindingMap` (see core-dispatch.md §4) and `httpsrv`'s middleware/handler binding caches (§4 below).
  - `api.Late` (`api/poly.go:39`) — a "just give me the raw value, resolve its concrete type via the polymorphic envelope, but don't recurse infinitely" escape hatch used by `stdjson.typeContainer.UnmarshalJSON` and `MultipartMapper.Read`.
- **MIME/Content** (`api/mime.go`): `Content` interface (`MediaType()/Metadata()/Body()`), `ParseMediaType`/`FormatMediaType` wrap stdlib `mime.ParseMediaType` into `maps.Format` (mapping direction To/From — see eventsourcing-support.md §Maps), `NewHeader`/`MergeHeader` build `textproto.MIMEHeader` from a `map[string]any` (slice values become repeated headers).
- **Multipart** (`api/multipart.go`, `api/parts.go`): `Part`/`PartContainer`/`PartBuilder`/`ReadPartsBuilder`/`WritePartsBuilder` model a MIME multipart message as domain types (not `mime/multipart` types directly in call sites). `MultipartMapper.Read/Write/WriteParts` (`api/multipart.go:20,111,124`) are **three `maps.It` handlers** keyed by `maps.Format` tags `from:"/multipart//"` / `to:"/multipart//"` (the `Format` prefix-match rule, `maps.FormatRuleStartsWith` — see eventsourcing-support.md). Non-attachment body parts are recursively resolved through `maps.Out[Late](composer, body, maps.From(ct, nil))` — i.e. multipart part decoding recurses back into the *same* format-dispatch pipeline used for top-level JSON, so a multipart part's body can itself be JSON, protobuf, etc. transparently.
- **`api.Result`** (`api/result.go`): tiny `Success[R](val R) either.Monad[error,R]` / `Failure(err) either.Monad[error,any]` helpers over `either.Right`/`either.Left`.
- **`api.Stash`** (`api/stash.go`): per-call-chain transient key/value store, itself dispatched through the *core* Handler mechanism rather than being ambient state: `Get`/`Put`/`Drop` are `handles.It` handlers on `stashGet`/`stashPut`/`stashDrop` callback types; `Provide` is a `provides.It` handler (tag `provides.Strict`) so `provides.Resolve` can also pull stashed values. A root Stash (`NewStash(true)`, installed once in `api.Installer.Install`, `api/feature.go:18`) answers "not found" as handled (empty) instead of `NotHandled`, so lookups don't propagate past the root; child stashes created per `Post`/`Send`/`Publish` call propagate misses upward via `NotHandled` (`api/stash.go:71-73`). `stashAction.CanFilter() → false` (`api/stash.go:44-46`) explicitly opts these callbacks out of the filter pipeline — a deliberate performance/semantics choice (stash ops shouldn't be interceptable/loggable middleware targets).

## 3. Routing & Scheduling

- **`api.Routes`** (`api/route.go:26`) is a `Constraint` + `FilterProvider` keyed by a `scheme:"..."` tag (`InitWithTag`, `api/route.go:57`), matched against `Routed{Message, Route}` callbacks. `PassThroughRouter.Pass` (`api/route.go:106`) and the HTTP-transport `Router.Route` (`api/http/router.go:62`, tag `scheme:"http,https"`) are two interchangeable `Routes`-scoped handlers for the same `handles.It` callback shape — a clean example of the port/adapter split the codebase's author cares about: `Routed` + `Routes` constraint is the **port**, `PassThroughRouter` (in-process) and `http.Router` (remote) are **adapters** selected purely by scheme string matching, with no direct coupling between them.
- **`batchRouter`** (`api/route.go:41`) coalesces same-route `Routed` requests arriving inside a `miruken.Batch` (see core-dispatch.md — batching) into a single `ConcurrentBatch` dispatched once `CompleteBatch` fires; results are demultiplexed back to individual callers via `promise.Deferred[any]` per pending request.
- **`api.Scheduler`** (`api/schedule.go`): `Concurrent`/`Sequential`/`Publish` are three `handles.It` handlers on `ConcurrentBatch`/`SequentialBatch`/`Published` callback types. Concurrent uses one goroutine per request + `sync.WaitGroup`; Sequential runs in-order and aborts the loop (not the whole request) on first failure, still returning partial results via `either.Monad`. `Scheduler.Constructor` uses `provides.It` + `provides.Single` (i.e. this handler is itself DI-constructed as a singleton — see core-dispatch.md §Lifestyles). `Scheduler.New` (`api/schedule.go:106`) again uses the multi-`creates.It`-with-`key` tag idiom (4 keyed bindings in one method) to make these container types constructible by string type-id for polymorphic deserialization.

## 4. HTTP Server

### Client side (`api/http/`)
- `http.Router.Route` (`api/http/router.go:62`) is the adapter mentioned in §3: builds an `http.Request` by running the outgoing message through `maps.Into` with a configurable `Options.Format` (default `application/json`), executes it through a caller-supplied `[]Policy` pipeline (`Router.invoke`, `api/http/router.go:144` — same "linked-list of `next()` closures" pattern used everywhere else in this codebase for middleware, e.g. `httpsrv.Pipe`), and decodes the response back through `maps.Out`. `BasicAuth(username,password)` (`api/http/basic.go`) is one `Policy` implementation. `newDefaultHttpClient` (`api/http/router.go:231`) hand-tunes `MaxIdleConns`/`MaxConnsPerHost`/`MaxIdleConnsPerHost` — a concrete, deliberate perf choice worth preserving in any refactor.

### Server side (`api/http/httpsrv/`)
- **Middleware pipeline** (`pipeline.go`): `Middleware`/`MiddlewareFunc` interface, `Pipe(middleware...)` builds a `next()`-closure chain identical in shape to `http.Router.invoke` above (this chaining pattern recurs at least 3 times in the codebase: filter pipeline, http client policy pipeline, http server middleware pipeline — a good candidate for a shared internal helper if a simplification pass happens). `M[M any](opts...)` (`pipeline.go:92`) resolves a *type* to a middleware instance three ways: (a) implements `Middleware` directly → `resMiddleware` (DI-resolved via `miruken.ResolveKey`), (b) has *some* method shaped like `(http.ResponseWriter, *http.Request, ...)` → discovered reflectively once and cached (`dynMiddleware` + `getMiddlewareBinding`, `pipeline.go:133` — copy-on-write `atomic.Pointer[map[reflect.Type]middlewareBinding]` guarded by a `sync.Mutex` on the write path, exact same idiom as `policy.go`'s `bindingMap`), or (c) panics if neither. `makeMiddlewareBinding` uses `miruken.MakeCaller` (core reflection helper — see core-dispatch.md §7) to build a cached, reflection-free-at-call-time invoker.
- **`Handler`/`HandlerFunc`/`Use`/`Api`/`H[H]`** (`handler.go`) mirror the middleware machinery exactly for the *terminal* handler instead of pipeline stages: `Use(ctx, handler, middleware...)` (`handler.go:46`) type-switches the terminal `handler` argument across 4 shapes (`http.Handler`, `httpsrv.Handler`, plain func, or "compatible function" via `funHandler.tryBind`) and wraps it with `Pipe(middleware...)`. `Api(ctx, middleware...)` (`handler.go:75`) is just `Use(ctx, H[*PolyHandler]())` — i.e. the generic polymorphic JSON endpoint is *itself* wired through the exact same declarative Handler-resolution machinery as any user handler, not special-cased. **Per-request scoping**: `baseHandler.serve` (`handler.go:212`) does `child := a.ctx.NewChild(); defer child.Dispose()` — every single HTTP request gets its own child `context.Context` (see setup-context.md), which is what makes `Scoped`-lifestyle bindings and the request-local `Stash` work correctly and get cleaned up deterministically.
- **`PolyHandler`** (`poly.go`) is the generic `/process` and `/publish` endpoint: validates method + `Content-Type` (`acceptRequest`), decodes body via `maps.Out[api.Message](h, r.Body, from)` where `from` came from parsing the `Content-Type` header, unwraps `Content` payloads, dispatches via `api.Publish`/`api.Send[any]`, and on the way out negotiates response encoding against the `Accept` header (`encodeResult`, using `github.com/timewasted/go-accept-headers`) with graceful fallback to `api.ToJson`. Errors go through `encodeError` → `maps.Out[int](handler, err, toStatusCode)` — i.e. **HTTP status code selection is itself a declarative `maps.It` mapping** (§ below), not a hardcoded switch in the handler.
- **`StatusCodeMapper`** (`error.go`): four `maps.It` handlers, each tagged `maps.Format to:"http:status-code"`, mapping `*miruken.NotHandledError`→404, `*api.UnknownTypeIdError`→400, `*validates.Outcome`→422, `*authorizes.AccessDeniedError`→401/403 (checked against an **optionally-injected** `security.Subject` via `_ *struct{ args.Optional }, subject security.Subject` — a DI-resolved parameter, not a manual context lookup), `*json.SyntaxError`→400. This is the cleanest example in the whole `api/` tree of the "declarative cross-cutting concern, zero infrastructure-aware controller code" ideal from the project's architecture doctrine: adding a new error→status mapping means adding one small `maps.It` method, not touching `PolyHandler` at all.
- **`Config`/`New`/`ListenAndServe`** (`config.go`): thin wrapper over `http.Server` with sane defaults via `internal.DefaultValue` (8080, 1s/1s/2s/30s timeouts, 1024-byte header cap — the header cap default looks unusually small for production workloads and is worth flagging if a config-hardening pass happens).
- **`feature.go`**: `httpsrv.Feature()` depends on `http.Feature()` (client-side, because `Router` types are shared) and registers `PolyHandler` + `StatusCodeMapper`.

## 5. Auth Middleware (`api/http/httpsrv/auth/`)

Thin HTTP-side wiring over the `security/login` port (full detail: `reference/security-validation.md`). `Authentication` (`middleware.go`) implements `httpsrv.Middleware`; it's configured with one or more `flowSpec{ref or flow, scheme}` via `WithFlowAlias(...).Basic()/.Bearer()/.Scheme(...)`. On each request it iterates configured flows, asks each `Scheme.Accept(r)` (implemented by `Basic`/`Bearer` — `basic.go`, `bearer.go`) to extract credentials from the request into a small `miruken.Handler` of login-callback responders (`callback.NameHandler`/`callback.PasswordHandler`), then drives a `login.Context` (JAAS-style login module chain) to produce a `security.Subject`. On success it calls `n(miruken.BuildUp(h, provides.With(sub)))` — i.e. the authenticated `Subject` becomes DI-resolvable for everything downstream (that's how `StatusCodeMapper.AccessDenied` above gets its optional `security.Subject` parameter). On failure it calls `Scheme.Challenge` to set `WWW-Authenticate` and the response code. If no flow matched and auth isn't `Required()`, it still injects an *unauthenticated* `security.NewSubject()` so downstream code can uniformly depend on `security.Subject` without nil checks.

## 6. OpenAPI (`api/http/httpsrv/openapi/` — separate go.mod)

Separate module (`go.mod`: requires `getkin/kin-openapi`, `Rican7/conjson`, `santhosh-tekuri/jsonschema`, etc.) so that schema-generation dependencies never bleed into the core `miruken` or `httpsrv` module's dependency graph for consumers who don't need OpenAPI — a deliberate, correctly-drawn module boundary.

Mechanism: `Installer` (`Feature(base *openapi3.T, config...)`) registers itself as a **setup Observer** (`b.Observers(i)`, `feature.go:72` — see setup-context.md for the Observer/lifecycle-hook contract) and implements `HandlerRuntimeRegistered(runtime *miruken.HandlerRuntime)` (`feature.go:165`): for *every* handler type installed anywhere in the whole app, it walks that runtime's exported `handles.It` bindings (`runtime.BindingsFor(i.policy)`, filtered by `miruken.Binding.Exported`) and reflectively generates an OpenAPI schema + `/process/<TypeName>` path per request/response type pair, using `openapi3gen` with a custom field-name camel-caser (`apiProfile.customize`). Bindings are grouped into an `apiProfile` per Go module (via `debug.ReadBuildInfo()` + longest-prefix match on package path, `apiProfile` at `feature.go:333`) so a multi-module app gets one OpenAPI doc per module rather than one giant merged doc. `AfterInstall` (another lifecycle hook) finalizes the docs and — interestingly — generates live JSON *examples* for every schema by round-tripping a zero-value instance through the **real** serialization pipeline (`maps.Out`, `generateExampleJson`) rather than synthesizing fake examples, so examples are guaranteed consistent with actual wire format including `@type` polymorphism tagging. `Surrogates(map[reflect.Type]any)` lets callers substitute the *wire* shape (e.g. `api.ConcurrentBatch` → `json2.Concurrent`) into schema generation so generated schemas match what actually goes over the wire, not the internal Go struct shape. `handler.go`'s `Handler(docs, enableCors)` serves the generated docs, keyed by a `mod` query param, with a small per-host/scheme `Server` URL rewrite cache.

## 7. JSON Mapping (`api/json/`, `api/json/stdjson/`)

- `api/json/error.go`, `api/json/schedule.go` define **surrogate types** (`json.Outcome`, `json.Error`, `json.Concurrent`, `json.Sequential`) implementing `api.Surrogate.Original(handler)` plus paired `SurrogateMapper.Replace*` handlers (each a `maps.It` handler tagged `to:"application/json"`) that convert the *real* domain type (`validates.Outcome`, generic `error`, `api.ConcurrentBatch`, `api.SequentialBatch`) into the plain-data surrogate before it ever reaches `encoding/json`. This is the general pattern used throughout: **domain types never implement `MarshalJSON`/`UnmarshalJSON` themselves** — wire-shape concerns live entirely in `SurrogateMapper` handlers, keeping `validates.Outcome` etc. free of `encoding/json` imports (hexagonal separation, cleanly done).
- `api/json/stdjson/mapper.go`: `Mapper.ToJson/FromBytes/FromReader` are the actual `encoding/json`-backed `maps.It` handlers (tags `to:"application/json"`/`from:"application/json"`), each DI-resolving `stdjson.Options` (custom `Prefix`/`Indent`/`EscapeHTML`/`Transformers`, e.g. the exported `CamelCase` builder wired through `Rican7/conjson`) and `api.Options` (polymorphism switch) via `args.Optional + args.FromOptions` (framework-supplied options-resolution convention — see core-dispatch.md/eventsourcing-support.md for `args.*`). When `Polymorphism == PolymorphismRoot`, marshal/unmarshal/encode/decode all delegate to `typeContainer` (`poly.go`) instead of calling `encoding/json` on the raw value directly.
- `stdjson/poly.go`'s `typeContainer` is the actual wire-format implementation of `@type`/`@values` polymorphism: on `MarshalJSON`, arrays get per-element type wrapping (recursing into nested `typeContainer`s when the element's runtime type differs from the declared slice element type or is `any`), then the type/value fields are spliced into the already-marshaled byte slice **in place** (byte-slice surgery — `copy(byt[len(typeProperty)+1:], byt[1:]); copy(byt[1:], typeProperty)`, `poly.go:92-95` — a deliberate micro-optimization avoiding a second full marshal pass; worth flagging as a hot path if a perf/readability tradeoff review happens). On `UnmarshalJSON`, it reads `@type`/`$type` (`KnownTypeFields`), resolves the concrete Go type via **`creates.Key[any](composer, typeId)`** — i.e. deserialization target-type resolution is delegated back into the core DI/covariant-`creates` policy rather than any static type registry — then recurses to unmarshal `@values`/`$values` into that instance, finally reconciling into the caller's target via `internal.CopyIndirect`.
- `stdjson/surrogate.go`, `message.go`, `schedule.go`, `either.go`: more `SurrogateMapper` handlers, notably `EncodeMessage`/`DecodeMessage` (wrap `api.Message.Payload` in a `{"payload": <raw>}` envelope, itself recursively serialized through the same `maps.Out[[]byte]`/`maps.Out[api.Late]` pipeline) and `Either[L,R]` (surrogate for `either.Monad`, storing the resolved branch as `left bool` + raw JSON `value`, resolved back through `Original` by re-decoding with `api.FromJson` and type-asserting to `L`/`R`).
- Root `maps/` package (full detail in `reference/eventsourcing-support.md` §Maps) supplies the `maps.It` policy, `maps.Format` (with `FormatRuleEquals`/`FormatRuleStartsWith` matching — used for both exact media types and multipart-style prefix matches) and `maps.Out[T]`/`maps.Into`/`maps.To`/`maps.From` helpers that every mapper handler above is built on.

## 8. Assessment

Overall the `api/` tree is a strong, consistent realization of the hexagonal ideal the project's global instructions describe: HTTP/JSON/multipart concerns are expressed as *handler methods with declarative tags*, not as branching logic inside a monolithic controller. `PolyHandler` and `StatusCodeMapper` in particular are close to the "every method body is `return HandledBy.app()`"-style thinness the doctrine calls for, just expressed as small focused Go methods instead of a single dispatch call, because the framework doesn't have a separate "controller" concept — the HTTP handler *is* the thin declarative edge, and the actual business logic lives in wholly separate `handles.It` handlers elsewhere in an application that never import `net/http` at all.

Concrete leakage/observations, not invented:
- `PolyHandler.ServeHTTP` (`poly.go:40`) and `Router.Route` (`api/http/router.go:62`) are the two places where `net/http` types genuinely have to meet the message envelope — that's expected and correctly contained (they are the adapters, by design), not leakage.
- `error.go`'s `StatusCodeMapper` is domain-adjacent code that *does* import `net/http` for status constants and reaches into `security`/`security/authorizes`/`validates` concrete error types — this is intentional cross-cutting glue (it's explicitly the "features on top of concepts" layer, not domain code), but it means adding a new domain error type that needs a specific HTTP status requires touching this file; that's an acceptable, singular integration point rather than diffuse leakage.
- `stdjson/poly.go`'s in-place byte-slice splicing (`poly.go:83-95`) is doing raw wire-format surgery outside `encoding/json`'s API — efficient, but the most "infrastructure-flavored" code in the mapping layer; it's appropriately confined to this one file rather than spread around.
- Three independent, structurally-identical "linked chain of `next()` closures" middleware implementations exist (`httpsrv.Pipe`, `http.Router.invoke`, and the filter pipeline in core `filter.go`) — not a hexagonal-purity issue, but a duplication worth consolidating in a future simplification pass.
- No direct evidence of client `net/http`/JSON types leaking into `es/`, `security/`, or `validates/` domain packages — those depend on this layer only through the generic `Surrogate`/`maps.It` seams, which is exactly the intended direction (features depend on concepts, never the reverse).
